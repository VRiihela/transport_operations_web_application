#### ISSUE 1 – `handleDayColumnClick` creates a new function on every render (performance + correctness)

```tsx
const handleDayColumnClick = useCallback(
  (day: Date) => (e: React.MouseEvent<HTMLDivElement>) => { ... },

);
```

`useCallback` wraps the outer function returning a new inner closure each render. The inner closures are new objects on each render regardless. This is a minor performance issue but the real risk is that `useCallback` gives false assurance of stability. Either remove the `useCallback` wrapping entirely (simpler) or inline the handler:

```tsx
onClick={(e) => {
  e.stopPropagation();
  setNewJobDate(dateAt8am(day));
}}
```

Same issue applies to `handleDayColumnKeyDown`.

#### ISSUE 2 – `dayHeader` click stopPropagation breaks semantic structure

```tsx
<div
  className={styles.dayHeader}
  onClick={(e) => e.stopPropagation()}
>
```

The day header is rendered *inside* the `role="button"` div. Stopping propagation on the header means clicking the header text does not open the New Job modal. That may or may not be intentional per the spec ("clicking the empty area of a day column"). If the day header is excluded, this should be documented. Additionally, a `div` with an `onClick` solely to stop propagation is an accessible anti-pattern — it will confuse screen readers since the div has no interactive role. If the intent is to exclude the header from the click target, restructure the layout so the header is a sibling of the clickable area, not a child.

#### ISSUE 3 – `role="button"` + `role="grid"` nesting is semantically invalid

ARIA spec forbids interactive roles (`button`) as direct children of `grid` role containers when the grid role is used. `role="grid"` implies the children should be `role="row"` containing `role="gridcell"`. Either:
- Remove `role="grid"` from the container (use `role="group"` or no role)
- Or restructure to use `role="row"` / `role="gridcell"` on columns
